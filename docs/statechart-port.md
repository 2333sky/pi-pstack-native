## How it ships

- `skills/statechart/SKILL.md` is generated by `scripts/semantics/generate.mjs` from `vendor/upstream/0.15.32/pstack/skills/statechart/SKILL.md`. The generated file keeps the pinned body verbatim under a platform-adaptation prelude, and adds the Pi execution tools footer.
- The 27 upstream files under `skills/statechart/scripts/` are vendored and pinned. Their Git blob SHAs match the pinned commit tree.
- `npm run check:semantics` fails when a generated entrypoint drifts from its pinned source or the adapter.
- `npm run test:statechart` runs the vendored upstream suite. It is not part of `npm run check` or `npm run check:release`.
- The `Statechart toolchain` CI job installs Java and the pinned TLC jar, then runs the bundled CLI check and one `from-chart` round trip that writes `chart.png` and `summary.json`. It replaced the full suite, which did not finish on the runner.

## Upstream suite result

`npm run test:statechart`: 150 tests, 127 passed, 19 failed, 1 of the 150 skipped because it needs a PID namespace. The files are byte-identical to upstream, so the failures are environmental or upstream, not port drift.

## The 19 failures

Filesystem failure injection written for another OS:

- a file that is put in the output folder during a run stays, and the run exits 2
- a run that cannot rename keeps the folder that another run puts in place of its folder as soon as the run makes it
- a run that cannot rename replaces a folder that another run makes before its copy, and keeps one that another run makes during its copy
- a run that cannot rename stops when another run removes its folder during its copy and makes an empty one in its place, and keeps that folder
- a run whose input changes before `--png` renders stops before it renders, and keeps its files
- a run whose rename fails after it moves the output folder aside puts the folder back, or says where it is
- a run whose spec changes while it reads it leaves the output folder, and the run that read the new spec charts it

TLC graph dump and temp folder handling:

- a graph dump that grows past one string is stopped, and the rule results stay
- a state graph too large for one string prints the rule results, keeps TLC's output, and draws no chart
- an error after TLC runs keeps TLC's output, and the message names its folder
- each TLC run writes the standard modules in its own temp folder, so overlapping runs cannot rewrite them under each other

`--against` discrimination:

- from-spec --against checks the fields of a record that is a record in only some of the spec's states
- from-spec --against compares the code with the spec on the parts both have, and --expect-broken sets the exit code
- from-spec --against names the group when the mapping groups a state of the spec by a field that state lacks
- from-spec --against stops when the mapping reads a field that is a record in some of the spec's states and not in others
- from-spec --against stops when the mapping reads a field that one model has as a number and the other as a string
- from-spec --against stops when the mapping reads what the spec lacks through a spread, a later state, a field of another type, or a field some states lack

mise discovery:

- statechart.mjs finds TLC with the real mise when an untrusted mise.toml is next to the spec and above TMPDIR
- statechart.mjs shows why java cannot start TLC

## What is claimed and what is not

Claimed: the source is pinned, the entrypoint is generated from it, the scripts are vendored unchanged, and drift fails CI. The core flows work here. `from-chart` checks an agreed chart and draws it back unchanged, `from-spec` charts TLC's state graph, and PNG rendering runs.

Not claimed: behavioral parity. `PARITY.json` keeps `behavioralParity` and `behavioralAudit` at `not-claimed`, and this suite is the reason for `statechart`. Nineteen upstream tests do not pass on this environment, so a statement that the skill behaves like upstream would be unsupported.

## CI measurement

The first CI job ran the full suite. It was cancelled at the 20 minute limit on 2026-10-26 (run 40359842172, started 16:30:51, cancelled 16:51:06). With a 45 minute limit it was cancelled again (run 40365921686, started 17:09:12, cancelled 17:54:38). The same suite takes about 4 minutes on a developer machine, so the CI runner does not complete it in 45 minutes.

The job therefore runs a smoke instead: the bundled CLI check from `test/statechart.test.ts`, one `from-chart` round trip on `skills/statechart/scripts/test/regions.mmd`, and an assertion that `chart.png` and `summary.json` exist. That run needs TLC, so the job still installs Java and the pinned jar. Locally the round trip takes about 4.5 seconds.

## Open work
