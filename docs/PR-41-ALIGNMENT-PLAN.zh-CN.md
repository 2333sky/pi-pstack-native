# PR #41：向原版 pstack 靠拢的实施方案

## 目标和基准

以 `cursor/plugins` 的 pstack 0.15.36（`c742dd61706fbacc1b95f1a20b7b988cf096ce6c`）为对照，改善 Pi 上的配置、委派、候选比较、审查和交付体验。保留 Pi 的 provider/model 与权限边界，不能把 Cursor 模型名、云服务或私有接口当作 Pi 已有能力。

## 实施顺序

1. 同步上游源码、辅助资源、状态图工具链和清单；核对 0.15.32 以来的行为变化，更新适配映射、漂移检查和契约。尚未验证或无法映射的行为明确记录，不能因复制 Markdown 而声称已实现。
2. 重做 `/setup-pstack` 的默认配置和编辑路径：利用 Pi 实际可用的模型建立可审阅的初始映射与多席面板；允许保留现有配置、只改所需项和分配 Reflect 角色。配置与执行使用同一套路由；回退、重复模型和未配置的能力向用户说明。
3. 将 Arena / Architect 对齐上游的候选、交叉裁判、选取、整合和失败处理语义：选择不同于已知父模型家族的裁判；可用候选不足或裁判不可用时给出明确的退路和记录；仍检查候选所有权与新鲜度。Architect 还需保留理解问题和后续实现阶段。
4. 将 Interrogate 调整为隔离的对抗工作区：评审者运行复现并提交命令与输出，由独立执行路径复核后只保留已证实的发现；不得自动应用评审者的修改。
5. 补足可在 Pi 中实现的 Swarm 选择策略、Autopilot/Orchestrate 协调和任务路由；外部操作、权限、云隔离、MCP 和调度能力与 Pi 实际环境一致，不虚构等价实现。
6. 为每个行为和失败路径补充针对性测试，运行类型检查、仓库检查、Pi SDK/模拟服务端到端及安装验证；有条件时运行真实模型，记录其模型、提交和结果。更新 PR 描述和剩余差异。

## 验收边界

- 模型面板、单模型回退、交叉裁判、候选缺席、审查复现和结果整合必须有可执行测试；源文件和名称覆盖不等于行为等价。
- 未配置真实模型凭证或服务不可达时，不能把模拟服务测试写成真实模型验收。
- 不复制 Cursor 私有 API、绕过现有执行边界或把本地进程称为云代理；暂不可用的能力保留可见说明。
- 升级来源和通过测试不代表维护者已完成语义签署。

## 本次落地与剩余边界

- 已固定并核对 0.15.36 上游树；新增 Statechart 编译产物，确保安装到 `node_modules` 后仍可由 Node 启动。
- 已合入主分支新增的逐条注册表协议，并将当前记录及校验切换到 0.15.36；0.15.32 记录作为历史保留。
- 已增加可审阅的默认配置、局部编辑和 Reflect 角色路由；Arena 支持异家族裁判、无裁判交由协调者选择、候选掉队后保留已验证结果。
- 已增加隔离的 Interrogate 对抗与复跑会话、Architect 的后续实现节点，以及 Swarm 的 `first-pass` 和 `rank-all`。Interrogate 的模型报告仍须由协调者核对实际执行证据。
- Swarm 混合分片/竞赛仍需显式 DAG；Autopilot 的远程 PR 生命周期仍由协调者完成。Cursor 云代理、私有 watcher、自动化事件、实时 MCP 转发和独立云调度没有被冒充为 Pi 原生能力。
- 真实 Java/TLC 已用于新 Statechart 的 Counter 示例和安装包验证。完整新版 Statechart 套件在本环境受进程检查和资源条件影响，未记作通过；真实外部模型推理和真实远程交付仍待独立验证。
