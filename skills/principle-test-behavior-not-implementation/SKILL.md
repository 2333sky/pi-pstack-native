# Test Behavior, Not Implementation

Test through the interface users/callers rely on and assert literal observable outcomes, not the internal call choreography.

## Pattern

- Call the subject the way production callers do.
- Assert an exact returned value, emitted event, file/state change, response, or rendered behavior.
- Use mocks only at real external boundaries or to make a condition controllable, not as the primary assertion.
- Delete or rewrite tests that would pass even if imported collaborators returned nothing useful.

## Avoid

- Only `toHaveBeenCalled`, `toBeDefined`, `not.toThrow`, or absence assertions.
- Expected values generated by the same implementation under test.
- Tests that restate a config constant without exercising behavior.

## Proof

Imagine every imported helper returning `undefined`; if the test still passes, strengthen or remove it.
